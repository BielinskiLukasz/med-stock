<objective>
Fix CSV import so imported rows are attached to a real medicine_catalog entry
derived from the CSV's own name/category columns, instead of the hardcoded
`catalogId: 1` placeholder left by the catalog/stock split (D-16).

Purpose: `mergeCSVRowsToMedicines` currently has no way to map a CSV column to
'name' (MEDICINE_FIELDS only lists stock fields), so CSVColumnMapper's Preview
button — which is gated on `mapping.includes('name')` — can never be enabled,
and every imported row silently gets `catalogId: 1`. This makes CSV import
either stuck at the mapping step or, if bypassed, corrupts data.

Output: `mergeCSVRowsToMedicines` extracts `name` (required) and `category`
(optional) per row; a new `commitCSVImport` resolves each row to a real
`medicine_catalog` entry (case-insensitive dedup against existing entries and
within the same import batch, creating a new entry when none matches) before
inserting the stock rows, all inside a single `db.transaction()`.
</objective>

      `db.medicine_catalog.where('name').equalsIgnoreCase(name).first()`; if found, reuse its

      returned id. `category` is applied ONLY when creating a brand-new catalog entry — an
      existing match's own category is never overwritten by the CSV row's value. Because each
      `add()` commits inside the same open transaction before the next row's lookup runs, IndexedDB's
      read-your-own-writes semantics mean a later row whose name matches (case-insensitively) a
      name created earlier in the SAME batch resolves to that just-created entry — no separate
      in-memory map needed. Build the final `Omit<Medicine, 'id'>[]` (each row's non-name/category
      fields spread together with its resolved `catalogId`) and insert them all in one
      `db.medicines.bulkAdd(...)` call at the end. Return `{ importedCount: <final row count> }`.
