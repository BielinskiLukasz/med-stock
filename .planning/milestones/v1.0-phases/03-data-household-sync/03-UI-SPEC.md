## Interaction & Animation

### Data Screen Layout (All Sections)

1. **Default state:** Single scrollable page with three white card-based sections stacked vertically, separated by 16px (md) gaps
2. **Section styling:** Each section has:
   - 16px (md) padding inside the card
   - 1px light gray border or subtle divider line above (except first section)
   - Heading (h3, 16px / 500) at top of section
   - Description text (body, 14px / 400) below heading
   - Button(s) below text (Export/Import buttons are primary blue, Cancel is secondary)
3. **Full page padding:** 16px (md) on left/right, 0 on top (below tab bar), 80px on bottom (space for tab bar)

### Export Backup Flow

1. **Default state:** "Export Backup" button is enabled, ready to click
2. **During export:** Button is disabled and shows loading spinner (or "Exporting..." text with spinner icon)
3. **After success:** Success toast ("Exported: {date}") appears at bottom (non-blocking)
4. **User action:** No navigation away from Data screen after export

### Import JSON Backup Flow

1. **Default state:** "Import Backup" button is enabled
2. **User clicks:** Opens `<input type="file" accept=".json">` file picker (not File System Access API — fallback for iOS Safari per STATE.md note)
3. **File selected:** Trigger file parsing:
   - Read file as text
   - Parse JSON
   - Validate schema with Zod (D-50)
   - If validation fails: show error toast, do NOT proceed to dialog
4. **Validation passes:** Show confirmation dialog (D-48) with actual counts from current DB:
   - Dialog blocks interaction
   - Shows "Import backup?" title
   - Shows body text with {N} medicines, {M} locations counts
   - "Cancel" button closes dialog, "Import" button confirms
5. **User confirms import:** Execute atomic Dexie transaction to wipe and replace medicines, locations, history tables (D-47)
6. **Success:** Show success toast ("Imported: {N} medicines, {M} locations"), stay on Data screen
7. **Error during transaction:** Show error toast and roll back

### Import CSV Flow (Multi-Step)

**Step 1: File Picker**
1. User clicks "Import from Spreadsheet" button
2. Opens `<input type="file" accept=".csv,.xlsx,.xls">` file picker
3. File selected triggers Papa Parse

**Step 2: Column Mapping**
1. Parse CSV with Papa Parse; extract header row and first 5 rows of data
2. Display column mapper UI:
   - Table with rows = detected CSV columns (from header)
   - Each row has: CSV column name (left), "Map to field:" dropdown (right)
   - Dropdown options: name, category, location, expiryDate, openedDate, quantity, quantityUnit, notes, (skip)
3. Validation: If user tries to preview without mapping 'name', show error "Required field 'name' must be mapped before preview is enabled"
4. Once 'name' is mapped, enable preview button

**Step 3: Preview**
1. Display first 5 rows of mapped data in a read-only table
2. Columns = mapped field names (in order user selected)
3. Rows = first 5 medicine records from CSV (parsed + mapped)
4. Show row count badge: "{count} rows" (total row count in entire CSV file)
5. User can go back to column mapper to adjust mappings

**Step 4: Commit**
1. "Import {count} medicines" button (primary blue)
2. User clicks → execute Dexie insert (append to medicines table, not replace per D-53)
3. During insert: disable button, show loading state
4. Success: Show success toast ("Imported: {N} new medicines from spreadsheet"), close CSV import flow, return to Data screen
5. Partial success (some rows skipped): Show warning toast ("Imported with {X} rows skipped due to errors...")
6. Full failure: Show error toast ("Failed to import: {error message}")

### Sync with Household Section

1. **Display:** Read-only text instructions (no buttons per D-44)
2. **Content:** 4 numbered steps + important note about manual sync
3. **No interaction:** This section is informational only

## Responsive Design

**Mobile-first (primary target):**
- Data screen: Full viewport width, all three sections stacked vertically
- Sections: 16px padding, 16px gaps between sections
- CSV column mapper: Single column (CSV column name left, dropdown right), scrollable horizontally if needed
- CSV preview: Scrollable horizontally if many columns mapped
- Tab bar: 5 tabs evenly distributed (each gets ~20% width; may need text scaling on very small screens)

**Tablet+ (future — not Phase 3 scope):**
- Data screen: May center content with max-width, sections as cards in a grid
- CSV mapper/preview: May use multi-column layout for better readability

## Implementation Notes

**For Executor:**

1. **DataScreen layout:** Create single scrollable container. Use Tailwind `flex flex-col gap-4` for section stacking. Wrap in a div with bottom padding to avoid tab bar overlap.
2. **ExportSection:** Simple button + description. On click, call `exportToJSON()` from `src/lib/dataOps.ts` (new file), disable button during export, show spinner.
3. **ImportJSONSection:** File input + description. On file select, parse JSON, validate with Zod, show confirmation dialog with actual counts from `db.medicines.count()` and `db.locations.count()`, execute atomic transaction on confirm.
4. **ImportCSVSection:** Orchestrates multi-step flow. Use Papa Parse in `src/lib/csvOps.ts` (new file) to parse CSV. Store mapping state in a Zustand store or component state. Display CSVColumnMapper, then CSVPreview, then commit button.
5. **CSVColumnMapper:** Use shadcn Select components for dropdowns. Each row = one CSV column. Validate 'name' is mapped before allowing preview.
6. **CSVPreview:** Use shadcn Table component. Show first 5 rows of mapped data (preview only, read-only).
7. **SyncInstructions:** Static text with four numbered steps + note. No state needed.
8. **File picker fallback:** Use `<input type="file">` for all file picking (NOT File System Access API) to support iOS Safari standalone PWA mode (STATE.md blocker note).
9. **Toast notifications:** Use existing toast library from Phase 1/2 (likely `sonner` or shadcn `toast` component). Show success/error toasts with appropriate colors (success = green, error = red, warning = amber).
10. **Tab bar update:** Add 5th NavLink to `src/components/BottomTabBar.tsx` pointing to `/data` with label "Data".

**For Planner:**

- **New functions needed:** `exportToJSON()`, `importFromJSON()` (with Zod validation), `parseCSVFile()` (using Papa Parse), `mergeCSVRowsToMedicines()` (convert CSV rows to Medicine records)
- **New files:** `src/routes/data/index.tsx`, `src/lib/dataOps.ts`, `src/lib/csvOps.ts`, component files listed above
- **Database transactions:** JSON import requires atomic `db.transaction('rw', db.medicines, db.locations, db.history, ...)` to ensure all-or-nothing semantics
- **Schema validation:** Zod schema for imported JSON structure (must include medicines array, locations array, history array with correct types)
- **CSV parsing:** Papa Parse with dynamic header detection, type coercion, and error handling (skip invalid rows, collect error count)
- **Dates handling:** All date fields (expiryDate, openedDate) must be stored as YYYY-MM-DD strings per CLAUDE.md and Phase 1 decisions
- **Papa Parse integration:** Install `papa-parse` npm package; use `Papa.parse()` for CSV parsing with proper error handling
