# Phase 8 — UI Design Contract: Full Location Management

> Visual and interaction contract for Phase 8 frontend work. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Phase 8 gives users full control over every row in the `locations` table — predefined and
> custom alike: rename, hide/show, delete-with-reassign, and drag/button reorder. Covers
> LOC-01 through LOC-04. No new design system, color, typography, or spacing tokens are
> introduced — this phase extends the existing Locations screen (`src/routes/locations/index.tsx`)
> and filters six existing dropdown call sites. All net-new decisions are interaction and
> copywriting contracts for the rename/hide/delete/reorder flows.

## Spacing Scale

Standard 8-point scale (reused from Phase 5/7 — no changes):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps within a row (drag handle ↔ name ↔ badge ↔ actions) |
| sm | 8px | Compact spacing between row actions (hide toggle, up/down buttons, edit, delete) |
| md | 16px | Default row padding, dialog body padding |
| lg | 24px | Section padding (page header to list) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (not used this phase) |

**Exceptions:** Icon-only touch targets (drag handle, up/down move buttons, hide/show toggle) use a minimum **44×44px** hit area even though the visible icon is 16px (`h-4 w-4`) — same exception already established for the Phase 7 language toggle. Achieve via `Button` `size="sm"` with adequate `p-2`/`min-h-11 min-w-11` rather than shrinking the touch target to the icon's visual bounds.

## Color

No new color roles. All colors reused from Phase 7/v1.1:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` | Page background |
| Secondary (30%) | `--card` / `--secondary` / `--muted` | Row background on hover, dialog surface, muted "Hidden" row background |
| Accent (10%) | `--primary` | "Add location" button, "Save" (rename confirm), "Move & delete" confirm button, focus rings |
| Destructive | `--destructive` | Delete button (both variants), "Move & delete" confirm button when it results in a location deletion |

Accent reserved for: **Add location button, rename Save button, delete-dialog's non-destructive confirm affordances (Cancel is neutral/outline), and focus rings on the active drag/edit row.** Never apply accent to the hide/show toggle or reorder buttons — those stay neutral (`ghost` variant, `text-muted-foreground`) so they read as secondary row controls, not primary actions.

Hidden-row muting: `opacity-60` (or `text-muted-foreground` on the name) applied to the entire row — matches D-08's "visually muted/grayed" requirement without introducing a new color token.

## Location Row Interaction Design

**Row anatomy (left to right):**

```
[⠿ drag handle] [location name, truncated] [Hidden badge, if hidden] [↑] [↓] [👁/🚫 hide-show] [Edit] [Delete]
```

- **Drag handle** (`GripVertical` from lucide-react): leftmost, `cursor-grab active:cursor-grabbing`, 44×44px touch target, `aria-label={t('aria.dragHandle')}`.
- **Location name**: `truncate` (single-line ellipsis) with a native `title={displayName}` attribute so a long name is recoverable on hover/long-press. Resolves rather than defers overflow (see UI Considerations below).
- **"Hidden" badge**: `text-xs text-muted-foreground`, inline after the name, only rendered when `loc.hidden === true`. Text: `t('locations.hidden')`.
- **Up/Down buttons**: `ChevronUp`/`ChevronDown` icons, `variant="ghost" size="sm"`, disabled when the row is first/last respectively (`aria-label={t('aria.moveUp')}` / `t('aria.moveDown')}`).
- **Hide/show toggle**: `Eye`/`EyeOff` icon, `variant="ghost" size="sm"`, toggles `loc.hidden`. `aria-label` swaps between `t('aria.hideLocation')` and `t('aria.showLocation')` based on current state (mirrors the existing `aria.switchToPolish`/`switchToEnglish` swap pattern from Phase 7).
- **Edit / Delete**: unchanged from the existing screen (`t('locations.edit')`, `t('form.delete')`), now available on every row — the `{!loc.isDefault && (...)}` guard is removed per D-01/D-05.

**Predefined vs. custom locations now render identically** — no branch on `isDefault` in the JSX beyond what's needed for the seed-data migration itself.

## Delete-with-Reassign Dialog

Extends the existing `AlertDialog` already used for delete confirmation — do not introduce a new dialog primitive.

**Zero active references (D-11):**
- Title: `t('locations.deleteConfirmTitle')` (existing)
- Body: `t('locations.deleteConfirmBody')` (existing)
- Footer: Cancel (`variant="outline"`) / Delete (`variant="destructive"`, `t('form.delete')`)

**One or more active references (D-09):**
- Title: `t('locations.deleteReassignTitle')`
- Body: interpolated `t('locations.deleteReassignBody')` with the live count
- A `Select` (shadcn, newly wired) labeled `t('locations.reassignLabel')`, options = every other location **excluding the one being deleted and excluding hidden locations** (this dialog is an assignment surface, same rationale as D-06's "anywhere the user is assigning a location to stock"), plus a final option `t('locations.reassignOther')` mapping to `location: null`
- Footer: Cancel (`variant="outline"`) / `t('locations.confirmReassignDelete')` (`variant="destructive"`, disabled until a reassign target is selected)

Both variants stay inside the same `db.transaction('rw', db.locations, db.medicines, ...)` shape already used by `renameLocation`/`deleteLocation` — no UI-visible loading state is required beyond disabling the confirm button during the async call (button shows existing disabled/opacity styling, no new spinner component).

## Reorder UI (Drag + Buttons)

Per D-14, both mechanisms operate on the same list simultaneously — neither is a fallback hidden behind a toggle.

- **Drag:** `@dnd-kit/core` `PointerSensor` (mouse/touch/pen) + `KeyboardSensor`, `@dnd-kit/sortable`'s `verticalListSortingStrategy`. Dragged row shows `opacity: 0.5` (per `08-RESEARCH.md`'s reference implementation) and the rest of the list reflows via the library's built-in transform/transition — no custom animation code.
- **Buttons:** `ChevronUp`/`ChevronDown`, swap `order` with the adjacent visible row, then renumber contiguously (Strategy A from `08-RESEARCH.md` — simple integer reassignment, no fractional indexing library).
- **Hidden rows** (D-15) stay inside the same sortable list, draggable and button-movable, just visually muted (`opacity-60`).
- **"Other"** never appears as a row in this list (D-16) — filter it out before it ever reaches `@dnd-kit`'s `items` array; it is not a `Location` record.
- A one-line hint (`t('locations.reorderHint')`, `text-xs text-muted-foreground`) sits above the list on first render so the drag affordance isn't undiscoverable-by-default on touch devices with no visible cursor change.
