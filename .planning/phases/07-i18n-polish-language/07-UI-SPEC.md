# Phase 7 — UI Design Contract: i18n / Polish Language

> Visual and interaction contract for Phase 7 frontend work. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> 
> Phase 7 adds English / Polish language switching to the app. All visible text (labels, placeholders, toasts, error messages, status names, screen titles, category names, location names, and unit labels) displays in the active language. Language choice persists across sessions. Dates render in locale-appropriate format. Stored database values and user-typed content remain unchanged.

## Language Toggle UI

**Placement:** Inside `BottomTabBar.tsx`, added as a new action button (not a navigation tab).

**Visual Design:**
- Flag emoji showing active language: 🇬🇧 (English) or 🇵🇱 (Polish)
- Positioned as the rightmost element in the fixed bottom navigation
- No text label — emoji serves as affordance
- Click toggles language immediately; no confirmation needed
- Touch target: at least 44px × 44px (icon-only button with padding)

**Interaction:**
1. User taps flag emoji
2. Active language switches to the other language (English ↔ Polish)
3. All visible text updates immediately without page reload
4. Language preference saved to localStorage (`'medstock-lang'`)
5. Active language re-applied automatically on next session

**Styling Details:**
- Font size: match existing tab labels (text-xs, 12px)
- Responsive: same sizing and spacing on mobile and desktop
- No text label below emoji (space-constrained)
- Hover state: use text-gray-700 (inactive) to text-primary (active), matching existing NavLink hover behavior
- Accessibility: include `aria-label="Switch to Polish"` (active) or `aria-label="Switch to English"` (active)

## Date Formatting

**Contract:** Dates are formatted at the display layer only. Stored database values remain as `YYYY-MM-DD` strings (unchanged).

| Language | Format | Example |
|----------|--------|---------|
| English | `YYYY-MM-DD` | 2026-12-31 |
| Polish | `DD.MM.YYYY` | 31.12.2026 |

**Implementation:** Use a pure utility function `formatDate(dateString: string, lang: 'en' | 'pl'): string` in `src/lib/utils.ts` or `src/i18n.ts`. Do not use `Intl.DateTimeFormat` to avoid timezone edge cases on stored date strings.

**Applied everywhere:** Medicine cards, detail view, history entries, filter chip summaries, date picker displays, toast messages — any visible date uses locale formatting.

**HTML `<input type="date">` elements:** Left native (browser applies locale formatting). No manual override needed.

## Copywriting Contract

### Translation Coverage

**Scope:** All visible UI text must be translatable and display in the active language.

**Included:**
- Tab labels: "Medicines", "Dashboard", "Trash", "Locations", "Data"
- Screen titles and headers
- Form labels, placeholders, input helpers
- Button labels (Submit, Cancel, Add, Edit, Delete, etc.)
- Status labels: "Active", "Expired", "Opened", "ExceededOpenPeriod", "ManualActive", "ManualExpired"
- Category names: "Pain/Fever", "Vitamins", "Antibiotics", "Cold", "Digestion", "Skincare", "Other"
- Predefined location names: "Bathroom Cabinet", "Kitchen Drawer", "Bedroom Nightstand", "Medicine Cabinet", "Other"
- Unit labels: "tablets", "capsules", "ml", "g", "pcs", "patches", "drops", "doses", "days", "weeks", "months"
- Toast messages (success, error, info)
- Error messages and field validation text
- Empty state headers and body copy
- Destructive action confirmation text

**Excluded (user content — never translated):**
- Medicine names (typed by user)
- Custom category strings (typed by user)
- Custom location names (typed by user)
- Notes and custom text fields

### Primary CTAs (Unchanged from Phase 5)

| Element | Copy | Language Behavior |
|---------|------|-------------------|
| Add medicine button | "Add medicine" | Translated to "Dodaj lek" (Polish) |
| Create catalog inline | "Create '[entered name]'" | Dynamic; format string translatable |
| Save form | "Save" / "Save changes" | Translated |
| Delete/Move to trash | "Move to trash" / "Delete" | Translated to "Przenieś do kosza" / "Usuń" (Polish) |

### Empty States (Unchanged from Phase 5)

| Scenario | Heading | Body | Polish Equivalent |
|----------|---------|------|-------------------|
| No medicines | "No medicines yet" | "Add your first medicine..." | "Brak leków" / "Dodaj pierwszy lek..." |
| No search results | "No matches" | "Try a different name..." | "Brak wyników" / "Spróbuj inną nazwę..." |
| No stock entries | "No stock" | "This medicine has no active stock..." | "Brak zapasu" / "Ten lek nie ma aktywnych zapasów..." |

**Copywriting rule:** All UI-defined copy (not user-typed) must have translations in both `en` and `pl` objects. Keys are flat by namespace (e.g., `{ medicines: { title, empty }, dashboard: { ... }, status: { active, expired, ... }, categories: { ... }, locations: { ... } }`).

## Translation Infrastructure (Reference Only)

Phase 7 implementation uses a custom `useTranslation()` hook backed by TypeScript-typed dictionaries. Translation keys are defined in code, not externally. This section documents the contract for reference:

- **Hook:** `useLang()` returns `{ lang: 'en' | 'pl', t: (key: string) => string }`
- **Provider:** `LanguageProvider` wraps the app at root (in `App.tsx`)
- **Storage:** Language choice persists in `localStorage` under key `'medstock-lang'`
- **Type safety:** `TranslationDict` interface enforces that both language objects have identical keys at compile time

**No dependency added.** Uses React Context + plain TypeScript objects, no external i18n library.

## Component Updates

### BottomTabBar

**Modification:** Add language toggle button as the rightmost element.

**Structure:**
```
[Medicines] [Dashboard] [Trash] [Locations] [Data] [🇬🇧 / 🇵🇱]
```

- Language toggle button is flex-1 (same width as other tabs) or fixed width (e.g., 50px) — **planner decision**
- Uses same styling pattern as NavLink tabs (text-xs, gap-1 vertical flex)
- Emoji display only; no text label
- `aria-label` attribute identifies current language: `aria-label="Switch to Polish"` (when English active)

### Status Display (All Screens)

**Current behavior:** `calculateStatus()` returns canonical English strings (`'Active'`, `'Expired'`, etc.); `StatusBadge` components display them via lookup in `STATUS_LABELS` object (to be removed).

**Phase 7 change:** `StatusBadge` calls `t('status.active')` etc. instead of looking up `STATUS_LABELS`. No change to `calculateStatus()` return values — they remain English canonical keys for consistency.

### Category Display (Catalog Forms, Filters)

**Current behavior:** Categories stored as `CATEGORIES` array values (English keys); rendered as plain text.

**Phase 7 change:** Display-layer components call `t('categories.painFever')` etc. Stored DB values and code constants remain unchanged.

### Location Display (Location Picker, Cards)

**Predefined locations:** Known values from DB (e.g., `'Bathroom Cabinet'`) trigger translation lookup: `t('locations.bathroomCabinet')`.

**User-created locations:** Always shown as stored (no translation attempted).

**Special case:** `location: null` is translated as `t('locations.other')` when displayed.

### Quantity and PAO Units

**Current behavior:** Unit strings stored in DB and constants (e.g., `'tablets'`, `'days'`).

**Phase 7 change:** Display-layer components call `t('units.tablets')` etc. Stored values and constants remain unchanged.

## UI Considerations

**Explicit truths** (resolved — verification: explicit):

- "EN: `formatDate(dateString, 'en')` returns stored `YYYY-MM-DD` string unchanged; PL: `formatDate(dateString, 'pl')` returns `DD.MM.YYYY` via string split — no `Intl.DateTimeFormat`"
- "formatDate(null, lang) returns `t('dates.noExpiry')` — `'No expiry'` (EN) / `'Bez daty ważności'` (PL); translation key `dates.noExpiry` must be present in both language dicts"
- "3 empty-state variants defined with EN+PL heading + body: no-medicines (`'No medicines yet'`/`'Brak leków'`), no-results (`'No matches'`/`'Brak wyników'`), no-stock (`'No stock'`/`'Brak zapasu'`)"
- "Polish strings are longer than English; button containers expand, form labels wrap — layout must not clip or truncate translated text"

**Backstops** (resolved — verification: backstop):

- { statement: "Language toggle renders 🇬🇧 (EN active) or 🇵🇱 (PL active) in BottomTabBar rightmost slot with ≥44px touch target", verification: backstop }
