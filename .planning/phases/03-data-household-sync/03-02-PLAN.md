  exportToJSON function — async, returns Promise<void>:
    1. Reads db.medicines.toArray(), db.locations.toArray(), db.history.toArray() in parallel via Promise.all
    2. Constructs backup object: { medicines, locations, history }
    3. Calls JSON.stringify(backup, null, 2) to get a formatted JSON string
    4. Creates a Blob with type 'application/json': new Blob([jsonStr], { type: 'application/json' })

    7. Appends anchor to document.body, calls anchor.click(), then removes it from document.body
    8. Calls URL.revokeObjectURL to free memory
    Do NOT use any library for this — Blob API + anchor is the D-46 method.

  importFromJSON function — async, accepts data: BackupData, returns Promise<{ medicineCount: number; locationCount: number }>:
    1. Executes db.transaction('rw', db.medicines, db.locations, db.history, async () => { ... })
    2. Inside the transaction: await db.medicines.clear(), await db.locations.clear(), await db.history.clear()
    3. Then: await db.medicines.bulkAdd(data.medicines), await db.locations.bulkAdd(data.locations), await db.history.bulkAdd(data.history)
    4. Returns { medicineCount: data.medicines.length, locationCount: data.locations.length }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-selected file → JSON.parse | File content is untrusted; may be malformed or adversarially crafted |
| Parsed JSON → Dexie DB | Validated data enters the DB; Zod is the gate |
| DB → exported JSON → file system | All medicines + history leave the app as a plaintext file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | importFromJSON / BackupSchema | high | mitigate | BackupSchema.safeParse is called before importFromJSON and before any DB write. If safeParse fails, toast.error fires and the function returns without touching the DB (D-50). JSON.parse is also wrapped in try/catch to handle non-JSON files. |
| T-03-02 | Information Disclosure | exportToJSON / Blob download | medium | accept | Export is an explicit user action. The file contains all medicines + history (potentially sensitive health data). The file stays on device unless the user explicitly shares it. App is privacy-first by design — no auto-export, no cloud upload. Mitigating beyond explicit user action would contradict the app's model. |
| T-03-03 | Spoofing | ImportJSONSection file picker | low | mitigate | accept=".json" limits the file picker to JSON files. Zod schema validation catches files that appear to be JSON but have wrong structure (e.g., someone crafts a medstock-like file). Confirmation dialog shows actual record counts so user can notice unexpected data volumes. |
| T-03-04 | Denial of Service | importFromJSON bulkAdd | low | accept | A pathologically large JSON file (millions of records) could slow the transaction. For a household medicine inventory, the expected data size is tens to hundreds of records. No size limit is enforced — this is acceptable for the target use case. |
</threat_model>
